# Roadmap

## Enfoque

El roadmap avanza en fases pequeñas, verificables y reversibles. Cada fase debe
tener alcance, entregables, criterios de aceptación, riesgos y mecanismo de
reversión. No se inicia una fase hasta que la anterior esté verificada.

## Fase 0: Inventario y definición

**Estado: no ejecutada.**

La Fase 0 será exclusivamente:

- Inventario de repositorios, laboratorios y activos existentes.
- Evaluación de reutilización (REUSE BEFORE BUILD).
- Catálogo de herramientas, licencias y costes.
- Arquitectura de referencia y límites.
- Análisis de cobertura frente a los dominios objetivo.
- Backlog priorizado con criterios de aceptación.

La Fase 0 no implementa componentes, no despliega servicios y no modifica otros
repositorios.

## Fases posteriores

Las fases posteriores se definirán a partir del backlog de la Fase 0. Como
criterio general:

- Cada fase abordará un único objetivo verificable.
- Cada fase incluirá documentación, seguridad y observabilidad mínimas.
- Cada fase indicará qué es PoC y qué se apoya en práctica profesional real.
- Cada fase podrá revertirse sin afectar a fases anteriores.

## Criterios de aceptación por fase

1. Alcance y no-alcance documentados.
2. Decisiones de reutilización registradas.
3. Controles de seguridad aplicados.
4. Evidencia de verificación reproducible.
5. Coste y límites conocidos.
6. Plan de reversión.
